# 歌手图片匹配（Music Artist Cover）

Android 应用：读取本地自定义文件夹里的歌曲，按歌手从网易云音乐 / QQ音乐匹配并下载歌手图片，保存到另一个自定义文件夹。

## 功能

- **自定义歌曲文件夹**：系统文件夹选择器（SAF）指定目录，授权持久化，自动递归扫描 mp3 / flac / m4a / aac / ogg / wav / wma / ape 等音频。
- **专辑封面**：歌曲列表直接显示音频内嵌的专辑封面，取不到时显示音符占位图。
- **扫描缓存**：扫描结果（含标签解析出的歌手）会持久化到应用私有目录，**重开 App 直接还原、不再重扫**，只有点右上角刷新或换目录才重新扫描；卡片上会标注「扫描于 …」。
- **下载状态一目了然**：状态不再是「待匹配」，而是直接查保存文件夹——某位歌手的 `歌手名.jpg` 在不在，得出「已下载 / 部分下载 / 未下载」（无法识别歌手的显示「无法判断」）。
- **按歌手匹配**：歌曲库里可切换「歌曲 / 歌手」两种视图。歌手视图按歌曲数排序列出所有歌手，一位歌手一行，点进去就是按歌手匹配——**一次搞定这位歌手的全部歌曲**，不用一首首来。
- **搜索**：歌曲页右上角放大镜展开搜索框，**歌曲视图搜歌名或歌手、歌手视图搜歌手名**。匹配用归一化比对（忽略大小写、空格、全半角），中英文都能搜；搜索状态下「全选」只作用于筛出来的结果。
- **排序**：视图切换旁的下拉菜单可选排序方式，选择会被记住。
  - 歌曲视图：**未下载在前 / 最新在前 / 最早在前**（时间按文件修改时间）
  - 歌手视图：**未下载在前 / 作品最多 / 作品最少 / 最近添加**（最近添加 = 该歌手最新一首歌的时间）
  - **未下载在前**：已下载的沉底，未下载和部分下载的浮到顶部，适合接着上次的进度继续补图
- **返回顶部**：列表上滑（往前进）时右下角浮出小按钮，下滑（往回滚）或回到顶部时自动收起；多选模式下让位给底部操作条。
- **多选歌曲（默认关闭）**：列表展示封面、歌名、歌手、文件大小与下载状态。默认不显示勾选框，点右上角「多选」才进入多选模式，支持单选、多选、全选、清空；退出多选会清空已选。
- **歌手识别（含多歌手拆分）**：优先读取音频内置标签（标题 + 艺术家）；标签缺失时从「歌手 - 歌名.mp3」式文件名解析。歌手字段会按分隔符拆分——「郭静/韦礼安」识别为两位歌手，分别匹配；同时也识别 `、` `;` `&` `×` 以及 `feat. / ft. / with` 等写法。
- **单曲匹配（点按歌曲即可）**：直接点列表里的任意一首歌进入单曲匹配面板。面板主体是**这首歌各位歌手在保存文件夹里已经下载过的图片**——一眼看出下过没有、下的是什么；「平台结果」卡片把**平台切换、重新搜索/保存按钮、候选大图**合并在一起，不用上下找；候选可点按切换，也可**长按某张候选图直接把它保存到本地**（不必先点选、也不必用保存按钮），或**手动改名**后重搜（见下）。
- **手动改名**：候选卡右上角的「改名」按钮可以改这位歌手的搜索词（比如标签写错、或想用英文名搜），改完只重搜这一位，其它歌手的结果不动。**文件名仍按歌曲里的原始歌手名保存**，所以「已下载 / 未下载」的判定不会因为改名而失准。
- **多歌手可单独保存**：一首歌有两位以上歌手（如「郭静/韦礼安」）时，**每位歌手的框内各自带一个「保存这一位」按钮**，可以逐个确认逐个存，不必一次性全存；已存的会标「已保存」。顶部的按钮相应变成「全部保存」。单独保存不会关闭面板，方便接着处理下一位。
- **双平台来源（可排序）**：网易云音乐、QQ音乐。在「设置」页可用上下箭头调整优先级，匹配时按该顺序依次尝试，前一个没命中自动降级到下一个。
- **批量下载**：进入多选模式后，歌曲页底部会浮出操作条，可以直接勾选**下载平台**并点「批量下载」，不用再跳到设置页。**歌曲视图和歌手视图都支持多选**：歌曲视图按歌曲去重后逐位歌手处理；歌手视图直接对勾选的歌手逐个处理（一位歌手一次），两端都支持「全选 / 清空」。按拆分后的歌手去重，同一歌手只搜索/下载一次；结果写入自定义输出文件夹，文件名「歌手名.jpg」，非法字符自动替换。
- **保存会回查，不会谎报成功**：每次写入后都会**重新列一次保存文件夹**，确认文件真的在其中、且大于 0 字节，才记为「已保存」并更新状态。若写入实际没落地（保存目录失效、provider 静默失败等），会明确报出原因而不是显示「已下载」。保存成功后歌曲/歌手列表的「已下载」状态会立刻刷新。
- **覆盖旧图开关**：统一在「设置」页（默认开启），批量与单曲匹配共用。开启时保存前会**先清掉目标目录里所有同名文件**（含系统历史上自动加过「(1)」后缀的副本），再写入一份标准名文件；关闭则遇到同名直接跳过并标注「已存在」。文件名一律用**歌曲里识别出的歌手名**，与「已下载 / 未下载」的检测口径完全一致。
- **状态反馈**：实时进度条 + 「设置」页的结果列表（已下载 / 已存在 / 部分成功 / 未匹配 / 失败），失败项可单条重试。
- **本地检查**：「设置」页一键对比**歌曲里出现的全部歌手**与**保存文件夹里已有的图片**——列出缺失哪些歌手（带关联歌曲数，点按可直接开始匹配）、多余哪些图片文件（歌曲里找不到对应歌手），多余项支持多选批量删除，适合长期使用后清账。
- **设置与关于**：图片来源（可排序）、保存位置、覆盖开关、本地检查；底部「关于」显示版本与作者，可一键跳转项目仓库。

## 安装与使用

1. 安装 `app\build\outputs\apk\release\app-release.apk`（需要 Android 8.0 及以上）。
2. 打开应用，在「歌曲」页点按上方卡片，选择存放歌曲的文件夹，等第一次扫描完成（之后重开 App 会直接用缓存，不再重扫）。

### 按歌手匹配（推荐，歌手数远少于歌曲数）

1. 在「歌曲」页把视图切到**「歌手」**。列表按歌曲数从多到少列出所有歌手，每位显示：本地已下载的图、歌手名、关联歌曲数、已下载/未下载。
2. 点某位歌手 → 打开匹配面板（与单曲匹配同一个面板，只是目标换成了这位歌手）。
   - 想一次处理多位：点右上角「多选」，勾选歌手（可「全选」），底部操作条选好下载平台后点「批量下载」。批量模式每位歌手自动取**第一个名称已校准**的候选，跳过挑图这一步。
3. 面板顶部有 **「平台候选 / 参与的作品（N）」** 切换：切到「参与的作品」能看到该歌手在本地参与的全部歌曲，方便核对这位歌手到底对应哪些歌；切回「平台候选」继续找图。
4. 挑好候选后「保存图片」，这位歌手的全部歌曲状态会一起变成「已下载」。

### 本地检查（查漏补缺）

「设置」页的「本地检查」卡片，点「开始检查」后对比两边内容：

- **缺少 N 位歌手**：歌曲里有、保存文件夹里没有 `歌手名.jpg` 的，按关联歌曲数从多到少列出；**点某位歌手可直接打开它的匹配面板**补上。
- **多余 N 个图片文件**：保存文件夹里有图片，但歌曲里找不到对应歌手的（例如歌删了、图还在；或标签改过名）。勾选后点「删除选中」批量清理，支持全选/清空。
- 两边完全一致会显示「本地图片与歌曲完全匹配」。

检查结果基于点击那一刻的内容；做完全新的匹配或保存后会失效（需重新检查），避免展示过期结论。

### 单曲匹配

点列表里任意一首歌即可打开单曲匹配面板：

1. 面板顶部是歌名、歌手和当前匹配状态。
2. 紧接着是**「本地已保存的艺术图」**：这首歌的每位歌手各占一格，显示保存文件夹里已经下载的图片和文件名；没下过的明确标注「未下载」。用来快速判断这首歌下过没有、当前存的是什么。
3. **「平台结果」卡片把平台切换、操作按钮、候选结果合并在一起**：
   - 顶部是平台标签（网易云 / QQ音乐），点一下立即重新搜索；
   - 下面是「重新搜索 / 保存图片 / 关闭」；
   - 再往下才是每位歌手一块的候选（**大图** + 候选名字含别名 + 来源平台 + 其他候选缩略图，点按切换）。
4. 名称与歌曲一致的标注「名称已校准」，不一致会标红提示。
5. **歌手名不对时点右上角「改名」**：改成你想搜的词（英文名、修正后的名字都行），点「搜索」只重搜这一位，其它歌手不动。改过的会在名字下标注「按「xxx」搜索」。
6. 决定要下载就点保存按钮：**只有一位歌手**时用顶部的「保存图片」；**有两位以上歌手**时，每位歌手的框内会多出一个「保存这一位」，可以逐个存，顶部的按钮变成「全部保存」一次存完。存过的会在框内标「已保存」，单独保存不会关面板。
7. 是否覆盖旧图由「设置」页的「覆盖已有文件」开关统一决定。

### 批量匹配

1. 在「歌曲」页点右上角「多选」进入多选模式，勾选需要匹配的歌曲（可「全选」）。
2. 底部会浮出操作条：**下载平台**（与设置页共用同一份开关，两边实时同步）+ 「批量下载」按钮，按钮上会显示已完成进度。
3. 点「批量下载」开始；未选目录或没勾平台时底部会给出提示，按钮自动置灰。
4. 结果汇总在「设置」页的「匹配结果」里，未匹配或失败的条目可点「重试」。

## 数据来源（非官方接口）

两家平台都没有公开的「歌手图片」官方 API，本项目使用其公开的网页/移动端接口，均无需登录：

| 平台 | 搜索接口 | 图片地址 |
| --- | --- | --- |
| 网易云音乐 | `music.163.com/api/search/get?s=<关键词>&type=100` | 响应中的 `result.artists[].img1v1Url`（**1:1 歌手头像**），追加 `?param=500y500` 缩图；头像缺失才退回 `picUrl` |
| QQ音乐 | `c.y.qq.com/soso/fcgi-bin/client_search_cp?w=<关键词>&format=json`（必须带 `Referer: https://y.qq.com/`） | `y.gtimg.cn/music/photo_new/T001R500x500M000<mid>.jpg` |

两个接口都是非官方的，随时可能改版或限流。若有平台开始失败，界面上会标出失败原因，换用另一个平台即可。

其他可用的元数据源（未接入，备查）：**MusicBrainz**（CC0，含多语言别名如「周杰伦 / 周杰倫 / Jay Chou」，是做名称校准的最佳来源，限速 1 req/s）、**Cover Art Archive**（专辑封面）、**iTunes Search API**（有中文名，但 `musicArtist` 实体不返回图片）。

## 从源码构建

本机需要 JDK 17 与 Android SDK（`compileSdk 37`、`build-tools 36.0.0`）。

```
build-apk.cmd
```

脚本会依次：写 `local.properties` → 生成 `release.keystore`（若不存在）→ 执行 `assembleRelease` → 用 `apksigner` 签名并校验，产物位于：

```
app\build\outputs\apk\release\app-release.apk
```

手动构建等价于：

```
gradle assembleRelease
```

## 发布新版本

1. 改 `app/build.gradle.kts` 里的 `versionName`（`versionCode` 是时间戳，自动递增，不用管）。
2. 更新 `RELEASE.md`，它会作为 GitHub Release 的正文。
3. 执行 `build-apk.cmd` 构建并签名。
4. 提交并打 tag：
   ```
   git add -A
   git commit -m "release: v1.0.1"
   git tag -a v1.0.1 -m "v1.0.1"
   git push origin main refs/tags/v1.0.1
   ```
5. 创建 Release 并上传 APK（需要一个有 `repo` 权限的 Personal Access Token）：
   ```
   powershell -ExecutionPolicy Bypass -File create-release.ps1 -Token <TOKEN> -Tag v1.0.1
   ```
   如果走本地代理，追加 `-Prox http://127.0.0.1:7890`。

> 签名密钥 `release.keystore` 不在仓库里，请自行备份。丢失后新版本无法覆盖安装老版本。

## 技术栈

- Kotlin + Jetpack Compose + Material 3（自定义主题，主色 `#0F766E`）
- AGP 9.3.1 / Kotlin 2.3.21 / Gradle 9.5.0 / minSdk 26 / targetSdk 35
- 存储访问：Storage Access Framework（`ACTION_OPEN_DOCUMENT_TREE`），不申请任何存储权限。
  目录遍历**不使用 `androidx.documentfile`**：`DocumentFile` 只是个 URI 壳子，每读一次 `name`/`length`/`isDirectory` 都会单独发一次 ContentResolver 查询，几百个文件时会放大成几百次 binder 往返。改为自定义的 `DocumentQuery` 做**一次投影查询**把名字、大小、修改时间一并取回——扫描 1000 首歌从数千次查询降到几十次，刷新保存目录也从「每个文件一次」降到「整目录一次」
- 网络：`HttpURLConnection` + 平台内置 `org.json`，零第三方网络库
- 元数据：`MediaMetadataRetriever`
